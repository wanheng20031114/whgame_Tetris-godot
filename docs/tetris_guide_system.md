# Tetris Guide 教学系统

## 目标

`Tetris Guide` 是放在游戏大厅中的教学入口，定位是“可互动的学习百科”，不是未来要单独制作的 Practice Lab。

它要解决的核心问题是：新手不知道哪些消除有价值，也不知道为什么高手会主动准备 Tetris、T-Spin 和 Combo。

## 学习顺序

第一版采用以下路径：

1. 基础知识
2. Wall Kick 踢墙
3. Combo 连击
4. T-Spin Double

## 页面结构

### 总览页

总览页用于快速进入基础知识和各个教学章节。

应包含：

- 章节列表
- 推荐学习顺序
- 每个章节的查看与模拟入口

### 基础知识页

基础知识页改为百科入口，内部按主题拆成 4 个基础章节。它不是练习 Lab，而是帮助玩家先理解对战规则、攻击力和通用思路。

应包含：

1. 对战俄罗斯方块
   - 介绍攻击如何转化为垃圾行。
   - 介绍被攻击后攻击条如何上升，以及玩家如何通过消行抵消。
2. 消除造成的攻击力
   - 放置当前攻击力表。
   - 包含 Single / Double / Triple / Tetris / T-Spin / B2B / Combo。
   - 说明非 T-Spin 的 Spin 消行只按普通消行计算攻击。
3. 游戏技巧
   - 多准备高价值消除，但危险时先清线。
   - 留心垃圾与攻击条。
   - 阅读 5 个 Next 预览。
   - 保持可继续操作的堆叠。
   - 减少不必要的软降。
4. Replay 复盘与成长
   - 暂时保留占位。
   - 后续连接 Replay 系统，解释如何读 AI 分析和复盘自己的局。

基础知识页的内容应当是“百科式说明 + 图示 + 简单交互/演示”。不要把它写成大段论文，也不要像营销页面。每一节都要回答玩家当前最可能问的问题：这是什么、会发生什么、我该怎么判断。

### 章节页

每个章节保持统一结构：

- 介绍
- 适用场景
- 收益
- 操作顺序
- Tips
- 进入固定场景模拟

文案需要像玩家教程，不要像产品宣传或 AI 总结。少用“为什么重要”这类空泛标题，直接说明这个技巧是什么、什么时候用、怎么做、要注意什么。

### 演示区

演示区应模仿玩家的正常操作，而不是瞬间切换状态。

每轮演示流程：

1. 显示预设地形
2. 方块从上方出现
3. 显示当前动作，例如“右移到井上方”
4. 平滑移动或下落
5. 需要旋转时显示“顺时针旋转 90°”
6. 锁定
7. 高亮消除行
8. 消除
9. 停顿
10. 自动重播

## 初始模拟内容

### Tetris 四消

目标：用 I 方块竖直进入右侧井，完成 4 行同时消除。

需要展示：

- 井的位置
- I 方块横向移动
- 顺时针旋转 90°
- 硬降入井
- 四行消除

### Combo 3

目标：连续完成 3 次消行。

需要展示：

- 每一步都补线
- Combo 不断线
- 每次消除后进入下一段固定地形

### T-Spin Single

目标：通过旋转让 T 方块进入槽位，并完成 T-Spin Single。

需要展示：

- T 槽
- 方块移动到槽口
- 顺时针旋转 90°
- 再次旋转进入目标朝向
- 锁定并消除

### 其它 Spin

L/J/S/Z 等非 T 方块 Spin 可以作为进阶地形理解和补救技巧展示，但当前规则下不提供 Spin 攻击奖励。
如果它们完成消行，只按普通 Single / Double / Triple / Tetris 和 Combo 规则计算攻击。

## 视觉方向

- 明亮、平面化、干净
- 避免深色对战页的压迫感
- 左侧章节导航要有足够内边距
- 按钮状态必须清楚：普通、悬停、焦点、按下
- 演示棋盘不能过窄或过高，比例应服务于阅读

## 场景模块化准则

Guide 页面不能只由脚本临时拼 UI。需要保持“静态场景外壳 + 模块场景实例 + 数据绑定”的结构。

当前拆分：

- `guide_system.tscn`：总入口，包含背景、顶部栏、章节导航、内容承载区。
- `overview_page.tscn`：总览页结构，承载学习路径和章节卡片。
- `basics_page.tscn`：基础知识页结构，承载基础章节入口、对战说明、攻击力表、通用技巧与后续占位。
- `chapter_page.tscn`：单章教学页结构，承载标题、介绍、操作顺序、Tips 和右侧演示棋盘。
- `simulation_page.tscn`：固定场景模拟页结构，承载操作说明、按钮和可交互棋盘。
- `guide_scenario_runner.gd`：教学场景执行器，只负责棋盘状态、移动、旋转、锁定和消行。

脚本可以填充章节数据、绑定按钮和播放动作，但页面层级、主要容器和可视模块应当在 `.tscn` 中可见，方便后续像正常 UI 场景一样维护。
